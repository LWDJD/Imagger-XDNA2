---

## 1. 根因（实测数字）

`cast_a16bfacc16bfp_1056_3840⟧ 这一份"好件"：

| 量 | 值 |
|---|---:|
| 打包的 `_ctrl.bin⟧ | **8,496 B** |
| patch.json 里的补丁偏移范围 | **7,272 – 10,116** |
| 偏移是否越界 | **是**（10,116 > 8,496） |

对照官方 `cast_a16bfacc16bfp_1024_2560⟧：

| 量 | 值 |
|---|---:|
| buffer3（runtime_control_packet） | 36,000 B |
| 补丁偏移范围 | 7,212 – 28,620 |
| 偏移是否越界 | **否**（28,620 < 36,000）✓ |

**⇒ 官方件内部自洽；我们这份 `gl16_pack⟧ 的 patch.json 与包里那 8,496 B 的 ctrl.bin **不是同一代产物**。**
补丁表描述的是一个 **≥10,116 B** 的控制包，而包里装的是 8,496 B 的另一个版本。

这解释了为什么无论怎么调 `xrt_arg_idx⟧ 映射都报同一个错（我试过交换 idx1/idx2，无变化）——
**问题不在分组，在配套关系**。

---

## 2. 这对 G2 定性的影响

父会话的判断"G2 是 schema 映射错、成本远低于真编译"——**schema 那一半已经证实**（转换器工作正常，官方件结构完全对得上）。
但 **G2 还剩另一半**：

```
坏件 = schema 错（已修） + 补丁表与 ctrl.bin 不配套（未修）
```

而"补丁表与 ctrl.bin 配套"这件事**只能由同一次编译产出**——
即 `patch.json⟧、`_ctrl.bin⟧、`.bin⟧ 必须来自同一轮 AIE 编译。项目当年把它们拼错了代次。
**这一半回到"需要真编译"。**
