- [ ] 参考必须是**独立**的:不能用产品自己的 f32 参考当"官方"。

      (ZImagePipeline,同 prompt/seed/8 步);官方 latent 轨迹在
      `../zimage-port/_out/zimage_128_fixed.latents.npz`。

## 2. 计时闭合

- [ ] 每个 job 有 `timing.closure`:Σ桶、total、unaccounted、±1 s 判定。
- [ ] UI 显示**每一项**,包括排队、TE、调度、重试、启动/注册/载荷、扩散、
      器件尾、VAE 加载/解码/保存、复现门第二遍、收尾。
- [ ] 冷启动重试单独列出次数与秒数;不得藏进 total。
- [ ] Σ桶 == total ±1 s 是硬门;不通过就查,不许改门限。
- [ ] 反例:4×128² 的 263 s 里 108 s 是两次冷启动重试 + TE,旧 UI 只显示 3 项,
      和 154.9 对不上 263。

## 3. 实现选择声明

- [ ] 每个阶段写清楚跑在哪:NPU / CPU / 仿真(device-exact model)。
- [ ] 禁止把"device-exact 仿真"写成"在 NPU 上";禁止把 CPU 常驻写成 NPU。
- [ ] 若任务书声称某 NPU 实现"已有",先在树里验证文件存在;不存在就写清
      缺失路径与剩余工作,不半建、不冒充。
- [ ] 例:本轮 `t3_real_vae.onnx` 在 `public_work` 全树不存在;NPU VAE 只有
      kernel 级物料(conv/GN/upsample),整链未建 —— 因此 ③ 未达成。

## 4. 批语义门

- [ ] 批 N 的每一张图,与"同 seed 的单图运行"的 latents **逐字节**相同
      (`np.array_equal`,不是 PSNR、不是 allclose)。
- [ ] N > 4 至少跑一次(本轮 N=5 与 N=8)。
- [ ] 每图耗时随 N 的曲线必须呈现摊薄;loop 的每图时间应基本恒定
      (权重按图重读),摊薄来自 TE/启动/VAE 的一次性成本。
- [ ] 批 N 的 VAE 每图独立解码,seed 映射 `seed+b` 与单图一致。
