## 1. 尺寸算术

    128×256 → patch grid 8×16 → 128 image tokens(128 % 32 == 0,**无需 padding**)
    → SEQ = 32 + 128 = **160**(M=160,M/16=10,FFN 行块整除)

与 144×128 的 padding 分支无关:128 已经是 32 的倍数,`REAL_TOKENS=128, PAD_ROWS=0`。

**ip 数值自门**(`t20_ipgate.py`,合成 Q/K/V + 量化后 f32 参考):**corr 0.998866**,
mean|d| 0.0247,5 块分别 0.999115 / 0.999088 / 0.998600 / 0.998880 / 0.998644 ——
与 T18 的 ND=128 版(0.998995)同一量级。

**规则(T20 增补一条,实测得出)**:

* **FFN 行块**:任何 M 都能用"按 M 编译一次(≤128 行最稳)或 96 行块拼";M≥288 的单 dispatch
  在本设备上确定超时。
* **不要连续 launch 同一个镜像**:**同镜像背靠背的第二次 launch 不产生完成信号**(ERT 看门狗
  7.0 s 报 state 8),主机间隔 0–2000 ms 无效;中间插一次**别的 xclbin** 的 launch 即可
  (1.6 ms 的 ip 就够)。所有 FFN_BLOCKS>1 的形状由 `Dev.barrier` 自动处理。见 `T20-STATE8.md`。
* **ip**:ND=SEQ 是硬约束;L1 账 `Mq·KD·2 + KD·SEQ/8·9 + Mq·SEQ·2 + 6144 ≤ 65,536` 定 Mq。
  SEQ=96→96、128→64、160→32、288→16;416 起需要键分块。
* **投影**:交付 t7_p5(m=96)按 96 行块,任意 M,无需新镜像。
* **padding**:tokens % 32 ≠ 0 时补 x_pad_token + pos (0,0,0)(144×128 验证)。
