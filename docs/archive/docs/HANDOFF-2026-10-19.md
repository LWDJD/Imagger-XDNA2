```

```

**环境事实(全部有实测,别当 bug 修)**
1. 首 dispatch 0xC0000005 偶发(~50% 冷启动彩票)→ 自动换新进程重试 3 次;teardown 崩溃是常态,**退出码不可信,判据是 calls.json(dispatch 数/retries)**;
2. state-8 定律与 Dev.barrier(见 §2);
3. 机器快/慢双态(staging 22.6 vs 14.0 GB/s)→ 性能数必须同 session A/B,双状态都报;
4. 磁盘紧张(~0.9 GB)——构建前自查;.prj 用后清;大件进 _backup_staging 的 tar;
5. **DSH 沙箱 BUG(反复发作)**:会话临时目录被清 → 一切工具调用报 `windows-acl-run: --temp is not an existing directory`;**修复 = 提权(danger-full-access)重建该目录**(负责人已批流程:“缓存目录提权重建即可,我手动给你批准”);
6. aie 导入顺序:设计模块(改 sys.path)必须先于 `from aie.iron import`;to_stream 有"生产者元素是消费者元素整数倍"的编译期约束。

## 8. 历史教训精选(防重蹈;全链见各报告)

- **patchify patch-major**:图像“混乱”根因;host/device 共用 bug,位精确门抓不到(参照系自身错)→ 需要“对官方/外部参照”类门。
- **kgu=64 假墙**:T16 判 M=128 不可建,实为漏传 --kgu 8(交付命令带);复现他人失败必须逐参数照抄。
- **G_GU 改核数=换参考**(kk' 置换变 C 舍入链);**能算清就不 build**(多次省 build 的先例);**能藏在关键路径后的阶段不是瓶颈**(T12 归因反转:norm 非临界)。
- **xclbin 字节 ≠ 等价**(编译期 kwarg 进签名),用同 session 交错对照。
- **门下在 stage 边界**(R8:驱动拼装 bug 一度被误诊为算术误差)。
- ERT 只能传声明参数(多传一个 BO 即 0xC0000005);AIE API 对未对齐向量指针**静默下取整**。
- 墙表(T 系列全部实测):L1 61,696 B 可用(Kc=960 硬上限)、NH=5 最优、memtile 512 KB/6 MM2S/6 S2MM/48 BD、shim 16 BD/2-in-2-out、compute DMA ≤3 维、数据参数 ≤7、acquire(n>1) 非 Value、连续 acquire(1) 挂 ACQ。
